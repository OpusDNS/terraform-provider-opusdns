# opusdns_domain_dnssec (Resource)

Manages DNSSEC configuration for an OpusDNS domain. Supports two mutually exclusive modes: registry-managed (`enabled = true`, OpusDNS generates and publishes the DS records for the zone hosted at OpusDNS) and BYO records (`enabled = false`, supply `records` containing externally managed DS or DNSKEY data).

## Example Usage

```terraform
# Registry-managed DNSSEC: OpusDNS generates and publishes the DS records
# for the matching OpusDNS-hosted zone. `records` must remain unset.
resource "opusdns_domain_dnssec" "managed" {
  domain_ref = opusdns_domain.example.id
  enabled    = true
}

# BYO records: replace the registry-side DNSSEC data with the records below.
resource "opusdns_domain_dnssec" "byo" {
  domain_ref = opusdns_domain.example.id

  records = [
    {
      record_type = "ds_data"
      algorithm   = 13
      digest_type = 2
      key_tag     = 12345
      digest      = "ABCDEF1234567890ABCDEF1234567890ABCDEF1234567890ABCDEF1234567890"
    },
  ]
}
```

## Schema

### Required

- `domain_ref` (String) Reference to the domain whose DNSSEC configuration is being managed. Accepts either the domain id (e.g. `domain_...`) or the domain name (e.g. `example.com`). Changing this value forces a new resource.

### Optional

- `enabled` (Boolean) When `true`, DNSSEC is enabled in registry-managed mode: OpusDNS generates the keys for the matching OpusDNS-hosted zone and publishes the DS records to the registry. `records` must be unset or empty in this mode. When `false` (the default), the resource manages DNSSEC by replacing the registry-side records with the contents of `records`; if `records` is also empty/unset the resource clears any existing DNSSEC data.
- `records` (Attributes List) Externally managed DNSSEC records (DS or DNSKEY data). When set with `enabled = false`, these records replace the registry-side DNSSEC data on every apply. When `enabled = true` this list is populated from the API after enabling. (see [below for nested schema](#nestedatt--records))

### Read-Only

- `id` (String) Resource identifier (the domain reference used to manage DNSSEC).

### Nested Schema for `records`

Required:

- `algorithm` (Number) DNSSEC algorithm number (e.g. 13 for ECDSAP256SHA256).
- `record_type` (String) Record type: `ds_data` (DS record) or `key_data` (DNSKEY).

Optional:

- `digest` (String) DS record digest (hex-encoded). Required for `ds_data`.
- `digest_type` (Number) DS digest type (e.g. 2 for SHA-256). Required for `ds_data`.
- `flags` (Number) DNSKEY flags (e.g. 257 for KSK). Required for `key_data`.
- `key_tag` (Number) Key tag identifying the corresponding DNSKEY. Required for `ds_data`.
- `protocol` (Number) DNSKEY protocol field (always 3 per RFC 4034). Required for `key_data`.
- `public_key` (String) Base64-encoded DNSKEY public key. Required for `key_data`.
