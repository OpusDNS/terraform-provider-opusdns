# opusdns_vanity_nameserver_set (Resource)

Manages a vanity nameserver set in OpusDNS (`/v1/vanity-nameserver-sets`). A vanity nameserver set brands the apex `NS` and `SOA` records of DNS zones with your own hostnames instead of the OpusDNS system defaults. Assign a set to a zone with the `vanity_nameserver_set_id` attribute of `opusdns_zone`.

The API has no update endpoint for a set's defining fields, so `name`, `parent_domain_name`, `soa_rname`, and `hostnames` force replacement when changed. Only `is_default` is updatable in place. Provisioning is asynchronous: a newly created set starts in the `provisioning` status.

## Example Usage

```terraform
resource "opusdns_vanity_nameserver_set" "example" {
  name               = "Example Vanity NS"
  parent_domain_name = "example.com"
  soa_rname          = "hostmaster.example.com"

  # Hostnames are ordered; the lowest position becomes the SOA MNAME.
  hostnames = [
    "ns1.example.com",
    "ns2.example.com",
  ]

  # Make this the organization's default vanity nameserver set. Zones created
  # without an explicit vanity_nameserver_set_id inherit the default.
  is_default = true
}
```

## Schema

### Required

- `hostnames` (List of String) The fully-qualified vanity nameserver hostnames, ordered by intended position (the lowest position becomes the SOA MNAME). Forces replacement, as the API has no update endpoint for a set's hostnames.
- `name` (String) Human-readable name for the set.
- `parent_domain_name` (String) The parent domain used as the apex of the vanity NS zone. All `hostnames` must be subdomains of it. Forces replacement.
- `soa_rname` (String) The SOA RNAME (responsible-party email in DNS form, e.g. `hostmaster.example.com`) stamped verbatim into vanity-branded zones. Forces replacement.

### Optional

- `is_default` (Boolean) Whether this is the organization's default vanity nameserver set. When `true`, zones created without an explicit set inherit this one. Updatable in place. Defaults to `false`.

### Read-Only

- `id` (String) Mirror of `set_id`.
- `nameservers` (Attributes List) The nameservers in the set, ordered by position. (see [below for nested schema](#nestedatt--nameservers))
- `organization_id` (String) The organization that owns the set.
- `set_id` (String) The unique identifier for the vanity nameserver set (e.g. `vns_...`).
- `status` (String) Lifecycle status of the set (`provisioning`, `active`, `suspended`, `failed`, or `deleting`). Provisioning is asynchronous.
